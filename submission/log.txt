# Ghost Data Audit Agent: Short Architecture

## Contract

| `request_text` | Free-text body of the request |

**Output:** one row of `case_id, deletion_status, steps_json`

---

## Pipeline

```
REQUEST
  |
  v
1. INTENT (DECISION MODEL)
  |   Does the text actually ask for deletion? (any language)
  |   No -> NOT_APPLICABLE, steps_json = []   (stop)
  v
2. IDENTITY + RETRIEVE (CODE + DECISION MODEL)
  |   Identity (CODE + DECISION MODEL): email -> user_id -> all current + old emails/phones/hashes
  |             Decision model only judges fuzzy matches and decoys
  |             (tag as guess if below 60% confidence)
  |   Retrieve (CODE): for each system, pick newest snapshot <= audit_at
  |             Query it with the subject's identifiers (matched rows only)
  v
3. ANALYZE (CODE + DECISION MODEL)
  |   Read:  parse SQL / JSON / logs / PDFs (pypdf) / screenshots (Tesseract)
  |   State: per resource at audit_at -> present / absent / redacted / active
  |          (reported_status and reported_result are claims, not proof)
  |   Rules: deletion_rules.csv gives the action
  |          DELETE / REDACT / ANONYMIZE / RETAIN / TOMBSTONE
  |          Decision model judges the conditions
  v
4. VERDICT (DECISION MODEL)
  |   COMPLETE / INCOMPLETE
  |   (any wrong treatment or active flow/restore path = INCOMPLETE)
  v
5. PLAN + OUTPUT (CODE)
```

## Division of Labor

### CODE (deterministic)

- Identity lookup
- Snapshot selection
- Querying
- Parsing and state building
- Rule lookup
- Step ordering
- Validation and output

### DECISION MODEL

The decision model handles the judgment-heavy work:

- Intent detection in many languages
- Fuzzy identity matching
- Judging rule conditions
- The final verdict

---

## Core Principles

1. **Claims aren't proof.** Rebuild the true state from evidence.
2. **Time-bound.** Use only evidence captured at or before `audit_at`.
3. **Identity has history.** Use the full identifier set, not just the request email.
4. **Absence is evidence,** but only from a snapshot that covers that system.
5. **Not everything is deleted.** Some data must be retained, redacted, or anonymized.
6. **Recreation risk is a finding:** active data flows and restorable backups.
7. **The system only audits and plans.** It never deletes anything.
8. **Strict output contract:** fixed phases, operations, states, ordering, and `evidence_id` rules.
